# Security and deployment

The toolkit is intended for trusted previews you control. The overlay runs in the preview page. Other scripts on that origin can read the page and may be able to access the review capability or data. Use a separate preview origin without untrusted scripts, customer data, or production credentials. The API does not crawl or proxy preview URLs.

- **Keep grants private.** Review links contain a bearer capability in the URL fragment. The client removes it from the URL and keeps it in tab storage scoped to the API origin and session. Anyone with the link and optional passcode can act as that reviewer until the grant expires or is revoked. Use HTTPS for remote access. Treat the browser's session storage as accessible to scripts on the preview origin.
- **Separate reviewer and owner access.** The embed snippet never contains either credential. Mint owner and agent tokens at the server console, store them securely, and pass them only to the owner API. Revoke an API token with `docker compose exec api python -m app.cli revoke-token TOKEN_ID`. Revoke reviewer access through the grants API or expire the session.
- **Know what is stored.** Notes, replies, page URLs, selectors, labels, visible text excerpts and selected text are saved in PostgreSQL. URLs lose their fragments and common secret-looking query fields; that filter cannot identify every sensitive value. Use clean preview URLs. Unsent offline notes may remain in tab storage until delivery or until the tab closes. Closing a tab can discard unsent notes; use the **Saved** state before leaving.
- **Protect the API.** Keep the default loopback port binding and terminate TLS in a trusted reverse proxy. Keep the database off the public network. The bundled database uses a separate login without superuser rights for the API; use a dedicated database and a restricted login for an external PostgreSQL server. Rate-limit at the proxy using its real client address, limit request bodies to 64 KiB, and set header and request timeouts. Disable request-body and authorization logging, and bypass proxy caches for everything except versioned assets. The API adds bounded per-process limits; these are not a substitute for proxy controls. Do not forward arbitrary host or origin overrides to it.
- **Keep the instance secrets and database private.** The setup script generates fresh database and grant-signing secrets in `.env`. The server stores token and capability digests, hashes passcodes with scrypt, and keys request fingerprints. Keep the signing key stable across restarts and protect it separately from database backups. Back up the database; archiving or expiring a review restricts access and retains its records.
- **Treat notes as data.** Text feedback is rendered as text. If you use an agent, do not follow instructions embedded in comments or treat them as authorization to expose credentials, deploy, or send messages.

Report suspected vulnerabilities through the repository's **Security → Report a vulnerability** form. Include reproduction steps using a synthetic preview. Keep credentials, review links, or private preview data out of public issues.
